## 已確認的問題

### 1. 法人名稱對不上，AI 上游輸入資料錯誤

FinMind 實際回傳 Foreign_Investor、Investment_Trust 等英文名稱；fetch_real_chip_data 卻以中文「外資」「投信」篩選。兩檔原流程 Foreign_Buy／Trust_Buy 全為零，即使 API 成功也會靜默發生。
只在診斷中改成英文名稱，國喬 10/6～10/8 評分從 35 變 55；台化 10/5 從 60 變 80。修正資料後並非所有日期會變成 BUY，不能只修欄位就宣稱模型可靠。
10/14 台化的原始 RL 由 HOLD 變成 BUY，最終仍為 IGNORE；國喬則由 BUY 變 HOLD，說明資料影響需要逐段驗證，而非以兩檔期待答案調參。

### 2. 模型與最終仲裁的責任混在一起

國喬 10/12 已判 BUY；10/13、10/14 觸發五日均線乖離超過 8%，被 Sell_Signal 當成硬性賣出。10/14 原始 RL 是 BUY（66.6%），最終卻是 IGNORE。
台化 10/5～10/13 的案例交易日已判 BUY；10/14 也因五日均線乖離觸發硬性避險。過熱是風險資訊，但現有程式直接把它納入無條件 Sell_Signal。是否應如此處理必須跨股票驗證，不能因後來上漲就直接刪掉風控。
此外 held 分支要求 raw SELL、TD<=0 且信心>=55 才採納模型賣出。TD>0 時可輸出 WATCH，理由卻寫「Q-Learning 偏向續抱」。已用 raw SELL、TD+1%、信心90% 重現；這是理由與原始模型輸出不一致的程式問題。

### 3. 七法則細節被壓縮，沒有完整進入狀態

_market_state 僅含評分區間、趨勢二元值、MACD二元值、大盤二元值及合併風險二元值，共最多64種市場狀態。部分型態透過總分間接進入；紅肥綠瘦、連續小陽及新高／新量等細節沒有獨立維度。
趨勢的判斷又是 Trend_Up_Strong OR Close>MA20，所以嚴格趨勢未成立但站上月線，會與嚴格多頭排列共用相同趨勢值。國喬 10/6、10/7、10/8 被歸入相同狀態；10/8 雖 Trend_Up_Strong 已成立，原模型仍只認同一個類別而判 HOLD。

### 4. 不同入口使用不同訓練期間，TD 不能直接橫向比較

單股頁從 2023-01-01、網頁完整掃描從 2025-01-01、終端機／每日掃描從 2025-09-01 開始。
國喬 10/8 的 TD 分別為 -0.33%、+0.40%、+0.90%；台化 10/7 分別為 +1.66%、+4.20%、+6.66%。這是相同日期、股票卻不同訓練樣本造成的結果，不能當作同一個穩定的預測值。

### 5. 信心與評估沒有證明實際交易能力

信心由 tanh(Q值差距) 與狀態次數組成，範圍50～98%，不是經樣本外勝率校準。Q值差5、樣本20就能顯示97.9%，不需要任何獨立驗證成績。
TD 是 gamma=0.9 的折現日報酬總和估計，不是明確持有N日的可成交淨報酬預測。reward 使用收盤到次日收盤，與規則回測的次日開盤成交假設不同；兩者不可混為已驗證績效。
現有回測摘要只評估規則 Buy_Signal/Sell_Signal，未評估完整 TD/RL 仲裁策略。因此目前沒有完整交易層級樣本外證據可以支持這些信心百分比。

## 優先處理順序

1. 修正並驗證 FinMind 欄位解析，加上資料可用性訊息與失敗狀態。
2. 每筆輸出保留原始 Q 動作、TD、確切狀態樣本數、硬性／柔性風險條件及最終覆蓋原因，修正相矛盾的理由。
3. 統一模型訓練期間／版本及交易時點，建立完整仲裁策略的滾動樣本外回測。
4. 再驗證是否需要拆分趨勢與過熱狀態、加入七法則的獨立特徵；用其他股票與保留期間檢驗，不能只針對這兩檔校正答案。
