# mystockbot

台股策略掃描與 Streamlit 診斷介面。策略分析與訊號追蹤不代表券商成交。

## 執行

在 repository 目錄啟動網頁：

```sh
python run_app.py
```

啟動器使用 `.venv-app` 專用環境，第一次會建立環境並安裝相依套件；需可連線至套件來源。
既有環境會先檢查 Streamlit 版本及核心模組，再啟動伺服器，不更動系統 Python。
瀏覽器開啟 `http://localhost:8501`。停止時在終端機按 Ctrl+C。
可用 `python run_app.py --check` 只檢查環境，或 `python run_app.py --port 8502` 更換連接埠。

若使用系統舊版 Streamlit，可能在載入時出現 `Descriptors cannot be created directly`
（Streamlit／protobuf 不相容）。請改用上述啟動器；不用在系統環境降版 protobuf。
Codespaces 也使用同一個專用環境；更新設定後執行 Rebuild Container，於 Ports 開啟 8501。
Streamlit Cloud 的入口仍為 `app.py`，平台需從根目錄的 `requirements.txt` 安裝相依套件。

網頁選單：完整掃描、單股診斷、規則策略回測、歷史追蹤績效、大盤診斷、每日訊號清單。
歷史追蹤頁直接讀取 `line_push_log.txt` 與 `long_term_watchlist.json`，可篩選目前監控、
最少觀察日數，下載完整分析 JSON。無需下載新行情。

終端機掃描使用 `python STOCK_GOD.py`；離線追蹤分析使用 `python analyze_push_history.py`。
GitHub Actions 僅執行終端機掃描，不會啟動網頁。

## 解讀結果

- 規則回測採收盤訊號、次日開盤成交假設，含研究成本；勝率只計已平倉交易。
  持倉交易日數與完成交易筆數分開列出，並顯示最大回撤及未平倉狀態。
  單股頁的「規則回測交易紀錄（歷史模擬）」預設只列行情截止日前 90 日內最後 5 筆，
  可勾選查看整段期間最後 5 筆；行情截止日與最後規則交易日分別標示。
  此區不是當日 TD/RL 推播、每日清單或券商成交。當日存檔訊號請使用選單 6。
- AI 正類機率與時序留出驗證指標分開顯示；模型機率不等於交易勝率。
  GMM 分群編號沒有固定多空意義。
- 歷史追蹤使用推播參考價；最後觀察不等於出場，觀察缺漏可能低估回撤。
  缺乏股數及完整成交資訊，不能當作投資組合績效。
- 單股診斷沿用 BUY／SELL 同步訊號監控清單的行為，會寫入本機 JSON，
  不送出券商訂單，也不發送 LINE。既有加入日期及參考成本會保留，更新觀察高點。
  僅按「開始診斷」時同步；切換補充分析選項不重複寫入。完整掃描頁只顯示結果，不新增或移除清單。
- 行情／規則／TD/RL 與 AI 診斷結果暫存最多 5 分鐘，基本面最多 1 小時。
  行情快取依股票清單、起始日期與大盤區分，不混用其他頁面的短期資料；
  監控清單不快取，開始診斷／掃描時重新讀取。可按側欄「清除分析快取」後再次診斷。
- 單股診斷預設快速模式，計算七法則、技術籌碼、TD/RL 與既有風控。
  「補充分析（選用）」可勾選額外 AI 分類驗證（GMM／隨機森林）及基本面；
  未勾選時不建立補充分類模型、不下載它的歷史行情，也不查詢 Yahoo 基本面。
  主模型的訓練期間、epochs、進場條件及風控門檻保持原值。
  頁面顯示主分析實際耗時（可能命中快取），首次行情／法人下載仍受網路與資料來源速度影響。
  主診斷保存於目前瀏覽器工作階段，補充選項沿用同一份行情、持有情境與仲裁結果；
  儲存滿 5 分鐘後，下一次操作要求重新診斷。修改輸入後需按「開始診斷」，
  報告上方會標示實際診斷的股票。清除快取也會清除目前報告。
  TD/RL 預先計算歷史狀態與 reward，保留原本 epochs 與更新順序。
  同機 800 筆固定合成資料測量約由 11.29 秒降至 0.53 秒，輸出一致；
  此數字僅涵蓋 TD/RL 計算，不代表整個網頁或實際行情下載時間。

若舊核心回傳缺少 `state_support` 等仲裁欄位，新版介面會保留報告並標示缺失資訊，
不會以零樣本或無風險替代未知資料，也不會確認新的 BUY；SELL 風控仍可顯示。
請整套更新 repository 並重新啟動 Streamlit 服務，避免部署中混用新舊模組。
這是相容處理；僅憑錯誤截圖無法確定遠端程序當時載入的檔案版本。

若部署後停在 `from app_support import ...` 並顯示 `ImportError`，可先到
Streamlit Cloud 的 **Manage app → Reboot app** 重新啟動服務。
入口檔更新後，舊工作程序可能仍保留更新前的 `app_support`，造成新增函式找不到；
新版啟動時會核對輔助模組介面版本與必要函式，不符合時重新載入磁碟上的模組。
正常頁面操作不重新載入。磁碟檔案仍不完整時會顯示中文復原提示並停止分析，
完整匯入錯誤保留於服務日誌；請確認部署使用此 repository 的完整同一版本。
歷史分析模組改為開啟歷史頁時才匯入，該模組失敗不會阻止單股診斷頁啟動。

若畫面能分析，但顯示「核心回傳欄位不完整／狀態支持未提供」，表示仲裁回傳仍缺少
完整欄位，不能視為已修復核心。啟動時現在會核對輔助模組的來源摘要，
以及 `STOCK_GOD.py`、策略設定、規則回測、法人解析、交易日與通知模組的整組來源摘要。
來源變更時重新載入相依模組與核心，接著才綁定介面使用的設定／函式；正常操作不重新載入。
摘要納入分析快取與診斷保存版本，更新後不沿用舊核心產生的報告。
側欄「核心執行版本」可用來核對實際載入的計算版本。無法載入相符版本時停止分析，
不以不相符的核心繼續給出判定。repository 不再保存 Python 編譯快取 `.pyc`。

「模型原判 BUY → 最終 IGNORE」本身表示既有進場風控擋下模型偏買，
修復版本載入後仍可能出現；需查看同一報告的具體退出／避險觸發條件。
缺少法人資料仍保留缺失狀態，這次不會因此補成零或放寬進場門檻。

成本、可選參考價風控、LINE Secrets 與歷史證據見 [PERFORMANCE_REVIEW.md](PERFORMANCE_REVIEW.md)。
這些修正尚未證實能提高未來報酬。

## 進場通知與模型修正（2026-10-14）

`entry_watchlist.json` 是候選觀察清單，初始包含國喬、台化；與有成本紀錄的
`long_term_watchlist.json` 分開。完整掃描會持續檢查候選股，不依賴當天熱門股榜。

通知分成三類，優先列於 LINE 日報及網頁：

- `ENTRY`：模型與既有規則確認進場，法人資料完整、日線完成，且無進場風控阻擋。
- `SETUP`：既有趨勢／型態出現轉強，或資料、模型尚待確認；只是預警，不當作 BUY。
- `BLOCKED`：模型偏買，但既有風控禁止進場，明確列出阻擋原因。

通知包含日期、收盤參考價、觸發條件、原始模型／最終判定、Q 值與樣本支持。
月線×98% 僅為既有規則參考，不能保證成交；未完成日線不產生確認進場。
同股票、交易日及通知層級只確認一次；預警可升級為進場。LINE 完整傳送成功才記為已通知，
失敗保留待傳，但過期或已反轉的進場通知不會當作當前機會補送。

排程維持工作日台北時間 19:00；這次沒有增加盤中監控。網頁只顯示通知，不發送 LINE。
通知狀態保存在 `entry_signal_state.json`，GitHub Actions 與日誌一同保存。

## 每日四類訊號清單

每日完整掃描（終端機選項 1／既有 GitHub Actions）會先整理並存檔四類清單，再隨
第一段 LINE 日報送出，清單放在長篇個股說明之前：

- **關注**：空手的 WATCH，或模型偏買但最終被風控阻擋；後者明確標示禁止介入。
- **當日買入**：空手時正式判為 BUY 的系統訊號。
- **續抱**：掃描前已在監控清單且未觸發 SELL；資料不可用時改列「資料待確認」。
- **當日賣出**：掃描前已在監控清單，且正式判為 SELL 的系統訊號。

這些是訊號與收盤參考價，並非券商實際成交。本次沒有改變規則回測的次日開盤假設、
TD/RL 的收盤至收盤訓練報酬、風控及模型門檻。
只有日期與執行日相符、日線已完成且價格有效的資料，才確認本次的新買賣／續抱。
缺失、落後日期、未完成日線另列待確認，不將缺失持股自動標為續抱。

檔案位於 `daily_reports/YYYY-MM-DD.json`，日期採台北時間的掃描執行日。
檔案包含產生時間、行情日期、判定理由、原參考成本與報酬、模型版本、風控原因、
樣本及資料狀態，以及 LINE 的待傳送／成功／失敗狀態。
同日重跑更新關注／續抱狀態，保留當日先前已記錄的買入與賣出訊號；
因此同股票先買後賣可同時出現在兩類。每日檔案保留當日彙總，非完整逐筆交易帳本。
清單在監控清單新增／移除之前產生，賣出的原參考成本不會因移除而消失。
熱門股不再因單日漲幅低於 3% 而略過仲裁與清單整理。

同日內容未變且 LINE 已完整傳送成功時，不重送四類清單；原有其他日報段落仍沿用既有流程。
傳送失敗也保留每日檔案，同日再次完整掃描可重試；跨日不把昨日訊號補送成今日機會。
GitHub Actions 會把 `daily_reports/` 與監控清單、推播日誌一起提交回 repository。
排程沿用週一至週五台北時間 19:00，沒有新增另一個排程。

啟動 `app.py` 後選擇 **6. 📋 每日訊號清單**，可按日期與類別查閱，下載 JSON 或 CSV。
此頁只讀取本機部署中的存檔，不下載行情、不重跑模型、不改寫監控清單，也不發送 LINE。
首次合併後須等下一次完整掃描產生檔案；不會由舊日誌推測補造歷史買賣清單。

法人資料修正支援 FinMind 英文／中文名稱，缺失保留為缺失，不補成零或沿用昨日買賣超。
TD/RL 各正式入口統一從 `strategy_config.py` 的 `2023-01-01` 訓練，快取包含模型版本。
Q 偏好指數不是校準勝率；模型原判、仲裁覆寫原因及資料狀態分開顯示。
模型樣本不足、法人資料不完整或日線未完成時，暫緩確認新的 BUY；原有持倉風控仍可退出。

對照比較未支持全面放寬五日乖離退出，因此維持原預設政策。
研究模式 `TaiwanStockTradingSystem(..., extension_exit_mode='warning')` 僅供比較，
不會由每日排程或網頁預設啟用。沒有為兩檔案例調低買進門檻或改由七法則接管。
詳細數據與限制見 [調整驗證報告](diagnostics/tdrl_20261014/ADJUSTMENTS.md)。

## 是方歷史紀錄停在 2024 年的修正（2026-10-20）

已以是方 `6561.TWO` 重現截圖：行情至 2026-10-20，舊規則最後交易為 2024-11-22。
原因是 2024-11-06 的漲停支撐被無限向前延用，2025／2026 全部交易日都判為跌破支撐，
將已達評分門檻的候選訊號全部擋下。
修正為依原有 20 交易日、1～3 次漲停的視窗決定支撐是否有效，不再無限補值；
兩日連續跌破必須對應同一個有效支撐來源，新來源不沿用舊來源的前日跌破證據。
其他風控、買入門檻、訓練期間與成交假設保持原值；模型版本標記更新以區分結果。

相同輸入下，修正後規則最後交易延伸至 2026-10-14；這次比較的規則累積報酬由
原 +6.65% 變為 -11.33%，並未證明績效改善。恢復有效期判斷不代表能捕捉所有上漲。
資料、年度擋單筆數與完整風險結果見 [是方支撐有效期核對](diagnostics/ISFANG_SUPPORT_EXPIRY.md)。
先前報告保留其原始程式版本的結果，不作為此次版本的績效。
